# AI 视频创作 Studio 彻底 UI 重构方案

- 状态：产品方向草案，待细化评审
- 日期：2026-07-21
- 适用项目：`waoowaoo`
- 目标用户：希望快速产出可发布视频的普通内容创作者，而不是熟悉模型、任务流和提示词的内部用户
- 关系说明：
  - `ai-creation-workspace-ui-redesign.md` 记录七阶段工作台基线，不再作为目标信息架构。
  - `ai-video-creation-workspace-product-redesign.md`、`interaction-v3.md` 和 `guided-flow-v4.md` 仍保留业务状态与流程治理价值。
  - 本文进一步收敛为“对外产品级 Studio UI”，目标是从工作流后台转为作品驱动编辑器。

## 1. 结论

下一版 UI 不应继续围绕“阶段、运行中心、Run Stream、分析过程、任务详情”组织。

目标产品应转为一个 AI 视频创作 Studio：

```text
从：流程驱动 UI
到：作品驱动 UI

从：后台任务可视化
到：视频成果编辑器

从：运行中心和浮层
到：上下文 AI 助手和生成队列
```

用户第一眼看到的应该是正在创作的视频、文稿、分镜、镜头和时间线，而不是内部任务状态。

## 2. 外部产品观察

本方案只吸收业务产品形态，不照搬 UI 组件库或视觉风格。

### 2.1 Descript

Descript 的核心启发是“文稿就是视频的入口”。用户可以围绕文字进行粗剪、调整和生成，而不是先理解后台流程。

对本项目的启发：

- 内容创作阶段应像文稿编辑器，而不是任务结果页面。
- 文稿旁边应直接显示预计时长、画面建议、锁定状态和局部重生成入口。
- 画面、声音和字幕应和文稿段落建立明确绑定。

参考：<https://www.descript.com/tour>

### 2.2 Runway

Runway Agent 的启发是“作品居中，AI 和时间线围绕作品服务”。其 Agent 可以生成故事板、分镜、参考图，并在多镜头视频中进入时间线剪辑。

对本项目的启发：

- 分镜和镜头应成为中央画布，而不是藏在流程阶段里。
- 角色、重要道具、重复场景等跨镜头资产需要在分镜前被识别、生成和锁定。
- AI 助手应根据当前选中镜头、资产或文稿段落提供上下文动作。
- 时间线只应在镜头制作和剪辑成片阶段出现，不应在早期规划阶段强行展示。

参考：

- <https://help.runwayml.com/hc/en-us/articles/51601639579667-Creating-with-Runway-Agent>
- <https://runwayml.com/news/engineering/inside-building-runway-agent>

### 2.3 Adobe Express

Adobe Express 的启发是“生成能力在编辑器内作为工具面板出现”。用户输入提示词和起始图生成视频，但仍处在创作编辑器上下文中。

对本项目的启发：

- AI 生成入口应是侧边工具或上下文操作，不应使用全屏运行弹窗。
- 生成后应直接回到可编辑成果，而不是停留在日志或过程中心。

参考：<https://helpx.adobe.com/express/web/video-creation-and-editing/create-videos/generate-videos.html>

### 2.4 Canva Magic Studio

Canva Magic Studio 的启发是“低门槛、成果优先”。AI 是降低创作门槛的能力集合，不要求用户理解模型、编排和技术阶段。

对本项目的启发：

- 顶层文案和入口应围绕“生成视频初稿、完善分镜、制作镜头、导出成片”。
- 模型、任务类型、Prompt 模板、Run Stream 等内部词默认不暴露。

参考：<https://www.canva.com/newsroom/news/magic-studio/>

## 3. 当前 UI 的核心问题

当前实现的问题不是视觉细节，而是产品形态仍像内部工作流后台。

1. 用户看到的是阶段和任务，而不是作品本身。
2. “运行中心”抢占用户注意力，但它不是创作者的主要工作对象。
3. 弹窗、透明遮罩和浮动入口破坏连续创作，容易造成页面被挡住但用户不知道发生了什么。
4. 分镜、镜头、资产和文稿没有形成一个统一的创作画布。
5. 技术概念过早暴露，例如 Run Stream、分析模型、任务详情、生成日志。
6. 视觉上仍是卡片化后台，缺少对外创作产品的专业编辑器感。

## 4. 产品原则

### 4.1 作品永远居中

中央区域只放用户正在创作和编辑的成果：

- 文稿
- 分镜
- 镜头
- 资产
- 预览视频
- 时间线

后台任务只能作为辅助状态存在，不能成为主界面。

### 4.2 AI 是上下文工具，不是主页面

AI 助手根据当前选择提供操作：

- 重写当前段落
- 生成当前镜头候选图
- 修复角色不一致
- 重新生成失败镜头
- 查看生成日志

AI 不再以“聊天弹窗”或“运行中心弹窗”作为主要入口。

### 4.3 视觉资产是独立产品阶段

角色、重要道具、重复场景、载具、书封、Logo 等会跨镜头复用的对象，是分镜生成和镜头制作的一致性约束，不是 Draft 的附属信息，也不是 Board 内的普通设置。

因此它应成为独立顶层导航，位于 Draft 和 Board 之间：

```text
Draft 文稿
-> Visual Kit 视觉资产
-> Board 分镜
```

核心规则：

- Draft 负责“讲什么、怎么说”。
- Visual Kit 负责“核心对象长什么样、是否需要跨镜头一致”。
- Board 负责“镜头如何排列，并绑定已确认的视觉资产”。

### 4.4 顶层导航表达作品形态

顶层不再显示六阶段业务流程，而显示作品从初稿到成片的形态变化：

```text
起始 Start
草稿 Draft
视觉资产 Visual Kit
分镜 Board
制作 Produce
成片 Edit
导出 Export
```

内部仍可以保留业务状态机，但 UI 不直接暴露这些内部阶段。

### 4.5 技术过程默认折叠

用户默认只看到：

- 当前是否正在生成
- 生成了什么
- 是否失败
- 失败后能做什么

模型输出、推理过程、步骤日志、重试参数统一进入“生成日志”，默认折叠。

### 4.6 不使用全屏遮罩承载常规流程

全屏遮罩只用于真正需要阻断的确认，例如删除、覆盖、付费风险。

常规生成、查看过程、选择候选、编辑属性不使用阻断式弹窗。

## 5. 总体布局

目标桌面布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 / 模式切换 / 保存状态 / 分享 / 导出 / 设置       │
├──────────────┬──────────────────────────────┬────────────────┤
│ 素材与结构    │ 主创作画布                    │ AI 助手 / 属性栏 │
│              │                              │                │
│ 原文          │ 文稿编辑器                    │ 当前选中对象      │
│ 大纲          │ 视觉资产板                    │ 可执行 AI 动作    │
│ 资产          │ 分镜板 / 镜头生产看板          │ 问题与建议        │
│ 段落          │ 视频预览 / 时间线              │ 生成日志          │
├──────────────┴──────────────────────────────┴────────────────┤
│ 底部：生成队列 / 任务状态 / 时间线，仅在制作和剪辑阶段展开    │
└──────────────────────────────────────────────────────────────┘
```

响应式规则：

- 桌面宽屏：左侧素材与结构、中间主画布、右侧助手同时展示。
- 中等屏幕：左侧可收起，右侧变为可固定的 Inspector 抽屉。
- 移动端：主画布优先，左侧和右侧都改为底部抽屉。
- 常规抽屉必须 portal 到 `document.body`，避免嵌套 transform 容器导致定位和点击拦截问题。

## 6. 顶层信息架构

### 6.1 Start：项目起始页

用户目标：开始一个视频项目。

页面形态：

```text
你想做什么？

[AI 漫剧] [书籍导读] [广告短片] [历史故事]

导入材料：
┌──────────────────────────────┐
│ 粘贴故事、书稿、产品资料或链接 │
└──────────────────────────────┘

输出规格：
画幅 / 时长 / 平台 / 风格 / 语言

[生成第一版视频方案]
```

设计要求：

- 不堆叠大说明卡片。
- 默认表单应短，只收集足够启动的关键输入。
- 高级模型、质量阈值、并发策略进入设置，不在起始页展示。

内部能力映射：

- 保存项目配置。
- 识别视频类型。
- 初始化内容生成任务。
- 建立后续草稿和分镜的数据容器。

### 6.2 Draft：草稿

用户目标：确认视频讲什么，以及最终要说什么。

页面形态接近文稿编辑器：

```text
左侧：内容结构
  1. 开场钩子
  2. 冲突展开
  3. 高潮
  4. 结尾转化

中央：可编辑文稿
  每段旁边显示：预计时长、画面建议、锁定状态、问题数

右侧：AI 修改
  [缩短 20%]
  [更像短视频口播]
  [加强冲突]
  [重新生成本段]
```

设计要求：

- 文稿是主对象，不是“剧本生成结果卡片”。
- 段落支持锁定、局部重写、拆分、合并和顺序调整。
- 书籍导读显示解说文稿、来源依据、屏幕文字建议。
- AI 漫剧显示分场剧本、动作、对白和场景提示。

主动作：

```text
确认文稿并提取视觉资产
```

内部能力映射：

- `ContentPlan`
- `ContentReview`
- `storyToScriptStream`
- 内容重写任务
- 画面元素提取能力

### 6.3 Visual Kit：视觉资产

用户目标：确认角色、场景、重要道具等核心对象的视觉一致性，为分镜和镜头制作提供稳定约束。

这一阶段回答的问题不是“镜头怎么排”，而是：

```text
视频里哪些对象需要跨镜头保持一致？
它们分别长什么样？
哪些已经确认，哪些可以自动处理？
```

页面形态是视觉资产板：

```text
核心角色
  主角        [候选图 1] [候选图 2] [上传] [已锁定]
  反派        [生成候选] [待确认]

关键场景
  老宅大厅    [候选图 1] [候选图 2] [已锁定]

重要道具
  玉佩        [生成候选] [待确认]
```

资产分级：

```text
核心资产：主角、反派、重要场景、关键道具，必须确认或显式跳过。
辅助资产：普通场景、次要物件，可由系统自动生成候选。
一次性元素：不提前生成，在镜头生成时自动处理。
```

设计要求：

- 从已确认文稿中提取角色、重复场景、重要道具和其他跨镜头对象。
- 用户可以修改名称、描述、重要性和是否需要一致。
- 每个核心资产支持生成候选图、上传参考图、选择定稿图、重新生成和锁定。
- 上传参考图等同于直接创建候选资产。
- 已锁定资产作为后续分镜和镜头生成的硬约束。
- 修改已锁定资产后，不删除已有结果，只把受影响分镜和镜头标记为需要更新。

主动作：

```text
确认视觉资产并生成分镜
```

内部能力映射：

- 画面元素提取能力
- 角色、场景、道具资产数据
- 候选图生成任务
- 上传和选择资产图
- 资产锁定状态
- 下游影响范围标记

### 6.4 Board：分镜

用户目标：确认每个镜头怎么讲、怎么拍、需要哪些画面。

页面形态是分镜画布，而不是阶段列表：

```text
Scene 01  [缩略图]  旁白  时长  角色  场景  状态
Scene 02  [缩略图]  旁白  时长  角色  场景  状态
Scene 03  [缩略图]  旁白  时长  角色  场景  状态
```

点选镜头后，右侧 Inspector 显示：

```text
镜头 03

画面描述
旁白 / 对白
角色绑定
场景绑定
镜头运动
参考资产

[生成图片候选]
[重写镜头]
[锁定镜头]
[查看生成日志]
```

设计要求：

- 分镜卡是核心视觉对象。
- 镜头顺序可以拖拽调整。
- 分镜卡直接展示当前画面、旁白、时长、状态和问题。
- Board 使用 Visual Kit 已确认资产，只负责绑定和调整镜头，不负责核心角色、场景、道具的首次定稿。
- 技术步骤不进入主卡片，只在日志里折叠。

主动作：

```text
确认分镜并进入镜头制作
```

内部能力映射：

- `scriptToStoryboardStream`
- `Storyboard`
- `Panel`
- 角色、场景、道具绑定
- 画面提示词和镜头运动

### 6.5 Produce：制作

用户目标：把每个分镜变成可用图片、视频和声音。

页面形态是镜头生产看板：

```text
镜头   图片      视频      配音      状态
01     已完成    已完成    已完成    可用
02     已完成    生成中    待生成    处理中
03     失败      待生成    待生成    需处理
```

点选镜头后，右侧显示：

```text
镜头 03 生产状态

失败原因
推荐处理
可用参考图
视频模型
配音角色

[重试图片]
[生成视频]
[生成配音]
[修复一致性]
```

设计要求：

- 批量生成和单镜头生成并存。
- 失败、待处理和生成中一眼可见。
- 右侧问题面板集中处理异常，不在每个卡片里堆满按钮。
- 底部显示生成队列，但不阻断用户浏览其他镜头。

主动作：

```text
生成缺失镜头
```

内部能力映射：

- 图片生成任务
- 视频生成任务
- 配音任务
- 唇形同步任务
- 质量检查与自动修复

### 6.6 Edit：成片

用户目标：预览、调整和组合最终视频。

页面形态才进入真正时间线：

```text
上方：视频预览
左侧：素材库
中央：当前画面 / 选中片段
底部：视频轨 / 音频轨 / 字幕轨
右侧：字幕、比例、转场、质量检查、导出设置
```

设计要求：

- 时间线只在此阶段成为主对象。
- 支持预览、裁剪、调整顺序、字幕和音频。
- 不要求一开始就实现专业剪辑器完整能力，可先接入已有合并导出和预览能力。

主动作：

```text
生成预览成片
```

内部能力映射：

- 视频合并
- 字幕生成
- 音频拼接
- 导出任务

### 6.7 Export：导出

用户目标：得到可发布文件。

页面形态：

```text
导出版本
平台规格
质量检查
字幕语言
水印和封面
下载记录
```

主动作：

```text
导出视频
```

内部能力映射：

- 合并导出任务
- 文件存储
- 成本记录
- 下载链接

## 7. AI 助手与属性栏

右侧栏根据当前选中对象变化，不是固定聊天框。

### 7.1 选中文稿段落

显示：

- 段落摘要
- 预计时长
- 画面建议
- 来源依据
- 是否锁定

动作：

- 重写本段
- 缩短本段
- 增强冲突
- 改成口播风格
- 重新提取画面建议

### 7.2 选中分镜

显示：

- 镜头编号
- 画面描述
- 角色和场景绑定
- 旁白
- 镜头运动
- 问题和质量状态

动作：

- 生成候选图
- 重新生成镜头描述
- 调整镜头运动
- 修复角色不一致
- 锁定镜头

### 7.3 选中资产

显示：

- 资产名称
- 标准描述
- 当前采用图
- 候选图
- 使用该资产的镜头

动作：

- 生成候选
- 上传替换
- 设为定稿
- 锁定核心资产
- 更新受影响镜头

### 7.4 选中时间线片段

显示：

- 片段时长
- 视频源
- 音频源
- 字幕
- 转场

动作：

- 裁剪
- 替换镜头
- 重新生成片段
- 调整字幕

## 8. 生成状态与日志

生成状态不再用“运行中心”表达。

统一为三层：

### 8.1 顶部轻状态

```text
正在生成 3 个镜头   预计 2 分钟   [查看队列]
```

### 8.2 底部生成队列

```text
镜头 02 视频生成中
镜头 03 图片失败，等待处理
文稿段落 04 重写完成
```

### 8.3 折叠生成日志

高级入口：

```text
[查看生成日志]
  内容规划        已完成
  文稿生成        已完成
  分镜生成        已完成
  图片生成        失败
  模型输出        折叠
```

规则：

- 日志不自动弹出。
- 日志不遮挡主画布。
- 失败时先显示业务原因和建议动作，再允许查看技术日志。
- 模型推理过程默认不展示，除非作为高级调试信息。

## 9. 状态模型

UI 不直接消费底层任务状态，而消费产品级状态。

建议产品状态：

```text
empty        尚未生成
drafting     用户正在编辑
generating   正在生成
needs_review 生成完成，等待用户确认
locked       用户已锁定
stale        上游修改后需要更新
failed       生成失败
```

典型对象：

- 文稿段落
- 核心视觉资产
- 分镜镜头
- 视觉资产
- 镜头图片
- 镜头视频
- 配音音频
- 成片版本

内部任务状态通过适配层映射到产品状态，不直接出现在 UI 主层。

## 10. 视觉方向

这不是继续改玻璃拟态。

目标风格应接近专业编辑器：

- 中性背景，低装饰。
- 主画布占最大面积。
- 左右工具栏紧凑稳定。
- 按钮数量受控，主要动作唯一。
- 信息密度高，但层级清楚。
- 少用大圆角、大渐变、大悬浮卡。
- 图像、镜头和文稿是第一视觉对象。
- AI 状态弱化成任务条和上下文动作。

推荐视觉关键词：

```text
Editor
Studio
Canvas
Timeline
Inspector
Shot board
Production queue
```

避免视觉关键词：

```text
Dashboard
Workflow admin
Run center
Glass cards
Floating modal
Task console
```

## 11. 与现有业务的关系

本方案不要求一次性重写后端。

推荐分层：

```text
新 UI Studio
  -> Product ViewModel / WorkspaceSnapshot
    -> 现有项目数据、资产、分镜、任务流、计费、存储
```

UI 只依赖产品级对象：

- `DraftSegment`
- `VisualKitAsset`
- `Shot`
- `VisualAsset`
- `ProductionItem`
- `TimelineClip`
- `GenerationJob`

适配层负责把现有数据转换为上述对象。

## 12. 实施建议

### Phase 1：独立 Studio 壳层

目标：

- 新增独立 Studio 路由或版本开关。
- 建立 Start / Draft / Visual Kit / Board / Produce / Edit / Export 顶层模式。
- 先使用 mock 或适配数据展示真实信息结构。

不做：

- 不改数据库。
- 不重写 worker。
- 不重写所有接口。

### Phase 2：Draft 和 Visual Kit 先落地

优先原因：

- 文稿决定视频讲什么，视觉资产决定角色、场景和重要道具是否一致。
- 先把一致性约束前置，后续 Board 和 Produce 的返工成本最低。

交付：

- 文稿编辑器式 Draft 页面。
- 视觉资产板式 Visual Kit 页面。
- 右侧上下文 Inspector。
- 折叠生成日志。

### Phase 3：Board 分镜画布

交付：

- 分镜画布式 Board 页面。
- 镜头和 Visual Kit 资产绑定。
- 镜头顺序调整、局部重写和候选图生成。

### Phase 4：Produce 生产看板

交付：

- 镜头图片、视频、配音统一生产状态。
- 批量生成队列。
- 失败处理面板。

### Phase 5：Edit 和 Export

交付：

- 初版时间线。
- 预览成片。
- 导出配置和下载。

## 13. 非目标

本方案当前不解决：

- 完整专业剪辑器。
- 多人协作。
- 评论和审阅。
- 多版本复杂回滚。
- 全部后端接口重写。
- 全部任务系统重写。

这些能力可以后续纳入，但不应阻塞 Studio 形态确认。

## 14. 验收标准

1. 用户第一眼能看到作品本体，而不是任务流程。
2. 顶层导航不出现内部任务名或 Run Stream。
3. 文稿、视觉资产、分镜、镜头、时间线成为主对象。
4. AI 操作跟随当前选中对象出现。
5. 生成日志默认折叠，不使用全屏运行中心。
6. 常规交互不使用透明遮罩阻断主页面。
7. 桌面端像编辑器，移动端像聚焦创作工具，而不是后台管理页。
8. 核心角色、重要道具和重复场景在分镜前完成确认或显式跳过。
9. 用户可以从材料导入一路推进到预览和导出，不需要理解内部任务编排。

## 15. 待讨论问题

1. 顶层是否使用 `Start / Draft / Visual Kit / Board / Produce / Edit / Export` 英文命名，还是全部中文化。
2. Draft 是否先支持纯文本编辑，还是直接支持段落级结构化编辑。
3. Visual Kit 第一版是否只做角色、场景和重要道具，还是同时覆盖书籍导读的书封、图表模板和引用卡。
4. 核心视觉资产未确认时，是禁止进入 Board，还是允许生成低保真分镜但禁止正式图片和视频生成。
5. Board 是否先使用列表式 shot board，还是直接做自由画布。
6. Produce 是否按镜头行展示，还是按状态泳道展示。
7. Edit 阶段第一版是否只做预览和排序，暂不做完整时间线。
8. 旧工作台是否保留为高级模式，还是迁移期只通过开关访问。
