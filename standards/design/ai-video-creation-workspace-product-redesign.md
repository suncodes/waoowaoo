# AI 视频创作工作台目标产品与重构方案

- 状态：目标方案已确认，待按 `WR-0` 至 `WR-6` 实施
- 适用项目：`waoowaoo`
- 更新时间：2026-07-18
- 目标用户：不熟悉模型、Prompt、工作流编排和视频制作术语的内容创作者
- 当前实现基线：`standards/design/ai-creation-workspace-ui-redesign.md`
- 质量与生成能力方案：`standards/design/video-generation-quality-optimization.md`
- 研究依据：七个开源项目与三篇 VideoLens 文章的评估结论统一沉淀在质量与生成能力方案第 3 节，本方案复用其阶段契约、能力路由、连续性资产、自动评审、灯光和调色基线等结论

## 1. 决策摘要

工作台不再围绕当前代码中的页面、Run Stream 或 JSON 产物组织，而是围绕用户真实参与视频制作时需要完成的决策组织。

目标一级流程统一为六个阶段：

```text
创作设定
  -> 内容文稿
  -> 画面设计
  -> 分镜预演
  -> 镜头制作
  -> 剪辑成片
```

核心决策如下：

1. 用户界面保持线性、稳定、可理解；底层继续使用有依赖关系的任务图、并行生成和定向回退。
2. 一级阶段必须同时具备明确目标、可查看产物、可执行操作和清晰的下一步。只读技术产物不单独占用一级导航。
3. `CreativeBrief`、`ContentPlan`、`DirectorTreatment`、`ProductionBible`、Run Stream 和质量 Artifact 保留，但作为阶段内能力，不直接成为普通用户需要理解的产品概念。
4. 默认允许 AI 自动连续执行；用户可以切换为分步制作，或在任意阶段选择“完成后暂停”。
5. 用户可以编辑、锁定、局部重生成和批准阶段产物。上游修改只标记受影响的下游需要更新，不直接删除已有结果。
6. AI 漫剧、书籍导读、广告、历史故事共享同一套六阶段骨架，只替换阶段内模板、资产类型、生成规则和质量标准。
7. 角色、地点和道具不按视频类型强制生成，而是统一识别“需要跨镜头保持一致的核心画面元素”。
8. 高成本图片和视频生成之前必须先完成核心画面元素确认和低成本分镜预演。

## 2. 当前产品问题

当前七阶段工作台解决了“看不到规划产物和运行进度”的问题，但仍存在以下产品缺口：

1. 一级导航混合了用户制作阶段、后台生成任务和只读技术产物。
2. “导读结构、解说稿、视觉方案”被拆成多个页面，但书籍导读在自动链路中并不是三个独立任务。
3. 内容策划和视觉方案只能查看，用户无法在进入分镜前纠正方向。
4. 书籍导读复用剧情剧本和资产界面，无法正确表达旁白、来源、图表、书封和关键载具等导读元素。
5. 固定展示四类运行任务，导致书籍导读出现永远“未开始”的不适用任务。
6. 资产库脱离制作流程，用户无法理解为什么需要先确认人物、场景或关键物件形象。
7. 默认界面暴露导演方案、视觉规范、原始 JSON 等技术信息，但没有突出普通用户真正需要做的决定。
8. 缺少上游修改后的影响说明、版本保留和定向更新，用户无法安全参与制作。

因此，本次目标不是继续给七阶段补按钮，而是重新定义用户可见的制作阶段和人机协作方式。

## 3. 产品设计原则

### 3.1 用户看到产物，不看到编排

用户需要知道“现在在写文稿”或“正在生成镜头”，不需要知道当前执行的是 `CONTENT_PLAN_RUN`、`VISUAL_PLAN_RUN` 还是 `storyToScriptStream`。

后台任务只在阶段内的“生成详情”中按需展开。

### 3.2 每个一级阶段必须可参与

一级阶段至少提供以下一种有效操作：

- 编辑核心内容。
- 选择或确认候选。
- 调整顺序、时长或绑定关系。
- 锁定满意结果。
- 局部重新生成。
- 确认并继续。

如果一个产物只能只读查看，应并入相关阶段的详情区，而不是继续拆成一级页面。

### 3.3 默认自动，人工按需介入

系统目标不是增加审核次数，而是让用户在需要时能介入，并把人工集中在以下位置：

- 创作目标和内容方向。
- 核心人物、场景、物件或载具形象。
- 分镜顺序、时长和信息密度。
- 自动质量评审无法稳定处理的异常。
- 最终成片验收。

### 3.4 先低成本确认，再高成本生成

内容、核心画面元素和分镜节奏没有确认前，不应批量进入图片和视频生成。

推荐成本顺序：

```text
文本计划
  -> 参考图和风格样张
  -> 分镜草图和临时旁白
  -> Animatic
  -> 最终图片
  -> 镜头视频
  -> 成片
```

### 3.5 用户界面线性，底层流程可回退

用户始终看到六个稳定阶段；系统内部根据修改内容计算影响范围并定向回退。

例如修改某段旁白时：

```text
旁白文稿已修改
  -> 对应分镜标记为需要更新
  -> 绑定资产继续保留
  -> 已生成且不受影响的其他镜头继续保留
```

## 4. 制作术语与用户命名

专业视频制作术语用于确定职责边界，但不直接作为普通用户的主标题。

| 用户界面名称 | 专业制作术语 | 核心问题 |
| --- | --- | --- |
| 创作设定 | Creative Brief / Development | 要做什么视频 |
| 内容文稿 | Editorial / Script | 视频具体讲什么 |
| 画面设计 | Art Direction / Asset Breakdown | 视频应该长什么样 |
| 分镜预演 | Storyboard / Animatic | 每个镜头如何安排 |
| 镜头制作 | Production / Dailies | 如何得到可用画面、视频和声音 |
| 剪辑成片 | Post-production / Delivery | 如何完成、检查和导出 |

以下内部术语不作为普通用户默认文案：

- `CreativeBrief`
- `ContentPlan`
- `DirectorTreatment`
- `ProductionBible`
- `ShotSpec`
- `VisualUnit`
- `Run Stream`
- `shadow / auto`
- `stale / blocked`

它们可以出现在开发文档、数据结构和高级详情中。

## 5. 六阶段目标流程

### 5.1 创作设定

#### 用户目标

明确“做什么、给谁看、做多长、采用什么形式”。

#### 默认内容

- 视频类型：AI 漫剧、书籍导读、广告、历史故事等。
- 原始材料：故事、书籍摘录、目录、笔记、产品资料或历史材料。
- 创作目标。
- 目标受众。
- 发布平台。
- 目标时长。
- 画幅。
- 剧透程度或事实要求。
- 参考风格和参考图片。
- 自动创作或分步制作。

#### 用户操作

- 编辑全部设定。
- 保存为模板。
- 选择自动创作或分步制作。
- 开始生成内容文稿。

#### 内部复用能力

- `VideoProfile`
- `CreativeBrief`
- 当前项目配置和来源材料

创作目标、受众和目标时长应在此阶段由用户可见、可编辑，不再只作为内容规划结果展示。

### 5.2 内容文稿

#### 用户目标

确认“视频讲什么，以及最终要说什么”。

#### AI 漫剧内容

- 故事结构。
- 场景和叙事节拍。
- 剧本、动作和对白。
- 时长与重复检查。

#### 书籍导读内容

- 导读标题和核心观点。
- 导读大纲。
- 完整旁白文稿。
- 每段来源依据。
- 屏幕文字。
- 预计时长。
- 事实、来源和剧透检查。

#### 用户操作

- 行内编辑。
- 拖动调整顺序。
- 增加、删除、拆分或合并段落。
- 重新生成选中段落。
- 锁定满意段落。
- 查看来源和检查问题。
- 确认并进入画面设计。

#### 内部复用能力

- `ContentPlan`
- `ContentReview`
- `GuideOutline`
- `GuideSegment`
- `Clips`
- 剧本转换和内容评审 Worker

当前“导读结构”和“解说稿”合并到此阶段。内容规划和文稿生成仍可作为独立后台步骤，但不再成为两个一级页面。

### 5.3 画面设计

#### 用户目标

确认“整条视频的呈现方式，以及哪些画面元素必须保持一致”。

#### 整体呈现

- 画面风格。
- 色彩感觉。
- 节奏。
- 主要画面类型。
- 转场和声音方向。
- 禁止出现的效果。

#### 核心画面元素

- 人物。
- 地点。
- 关键物件和载具。
- 书籍封面。
- 图表和引用卡模板。
- 其他跨镜头复用元素。

每个元素都要标记：

- 是否需要跨镜头一致。
- 标准描述。
- 候选参考图。
- 当前采用图。
- 是否已锁定。
- 可用变体。

#### 用户操作

- 修改整体风格描述。
- 使用图片或风格预设选择方向。
- 确认核心画面元素清单。
- 生成和选择标准参考图。
- 锁定人物、地点、物件或载具形象。
- 修改后只更新受影响的分镜。

#### 内部复用能力

- `DirectorTreatment`
- `ProductionBible`
- 当前角色、地点和道具资产库
- 图片候选、质量评审和自动修复

当前“视觉方案”和独立资产库重组到此阶段。普通界面展示通俗摘要，专业规则放入高级详情。

### 5.4 分镜预演

#### 用户目标

确认“每段内容对应什么画面、持续多久、整体播放是否顺畅”。

#### 默认内容

- 分镜卡片。
- 对应旁白或对白。
- 画面描述。
- 绑定的核心画面元素。
- 镜头类型和时长。
- 屏幕文字。
- 临时旁白。
- Animatic 时间线和播放预览。

#### 用户操作

- 拖动排序。
- 增加、删除、拆分或合并镜头。
- 修改画面描述。
- 更换绑定的核心画面元素。
- 调整时长。
- 重新生成单个分镜。
- 播放 Animatic。
- 确认后进入高成本镜头制作。

#### 内部复用能力

- `ShotPlan`
- `ShotSpec`
- `Storyboard`
- `Panel`
- 临时 TTS

分镜预演保留为独立阶段，因为它是内容和视觉设计转化为高成本生产前的必要决策点。

### 5.5 镜头制作

#### 用户目标

得到最终可用于剪辑的图片、镜头视频、旁白和声音素材。

#### 默认内容

- 分镜图片。
- 首尾帧。
- 镜头视频。
- 旁白配音。
- 背景音乐和音效。
- 自动质量检查。
- 自动修复历史。
- 需要人工处理的异常。

#### 用户操作

- 批量生成。
- 查看最佳候选。
- 手动选择候选。
- 修改单镜头要求。
- 局部重生成或修图。
- 锁定最终素材。
- 只处理异常队列。

#### 内部复用能力

- 图片生成和候选管理。
- 图片理解评审。
- `PromptPatch` 和有界自动修复。
- 视频生成门禁。
- 视频和配音生成。
- Run Stream 和任务恢复。

普通用户默认只看“最佳结果、处理状态、需要处理的问题”。Prompt、模型、评分和运行日志放入高级详情。

### 5.6 剪辑成片

#### 用户目标

完成全片编辑、检查和导出。

#### 默认内容

- 时间线。
- 镜头顺序和时长。
- 旁白、音乐和音效轨道。
- 字幕。
- 转场。
- 成片预览。
- 全片质量检查。
- 导出设置。

#### 用户操作

- 调整镜头顺序和时长。
- 修改字幕。
- 调整音乐和音量。
- 应用转场。
- 根据补镜建议返回对应阶段。
- 运行最终检查。
- 导出成片。

#### 内部复用能力

- 当前视频合并和播放能力。
- 后续 Rough Cut、Pickup List 和 Final QC。
- 导出与交付规格。

## 6. 人机协作模式

### 6.1 项目级制作模式

顶部使用分段控件提供两种模式：

#### 自动创作

AI 自动继续执行，以下情况暂停：

- 用户设置了检查点。
- 核心画面元素需要确认。
- 质量评审返回低置信度或人工处理。
- 即将进入批量高成本生成。
- 最终导出前。

#### 分步制作

每个阶段完成后等待用户确认。

用户可以随时切换模式，切换不取消正在运行的任务，也不清除已有结果。

### 6.2 阶段级统一操作

每个阶段底部保持一致的操作结构：

- 上一步。
- 保存。
- 重新生成选中内容。
- 完成本阶段后暂停。
- 确认并继续。

危险或高成本操作必须显示影响范围和费用/任务数量提示。

### 6.3 编辑与锁定

所有可编辑产物支持：

- `draft`：仍可被 AI 自动更新。
- `locked`：后续生成必须保持，不允许自动覆盖。
- `needs_update`：上游已修改，当前结果需要更新。
- `approved`：用户或质量流程已确认。

锁定应作用于具体对象，例如某个旁白段落、人物形象、潜水艇参考图或某个分镜，而不是只能锁定整个阶段。

## 7. 状态与依赖模型

### 7.1 用户可见状态

一级流程只使用普通用户可理解的状态：

```text
not_started   未开始
processing    AI 处理中
needs_review  待你确认
completed     已完成
needs_update  需要更新
blocked       有问题
```

“当前选中阶段”独立表达，不与阶段状态混用。

### 7.2 上游修改规则

上游修改后，系统必须先计算影响范围，再由用户选择是否更新：

```text
本次修改会影响：
- 3 个旁白段落
- 5 个分镜
- 4 个已生成镜头

[暂不更新] [只更新分镜] [更新全部受影响内容]
```

规则：

1. 不直接删除旧版本。
2. 不重生成已锁定且未受影响的对象。
3. 只把受影响对象标记为 `needs_update`。
4. 用户确认后再创建新版本或重跑下游。
5. 失败后保留上一次可用结果。

### 7.3 版本范围

首期不建设通用版本控制系统，只为关键产物保留有限版本：

- 当前采用版本。
- 上一个可用版本。
- 本次 AI 新版本。

支持比较、采用和恢复即可，避免过早引入复杂分支模型。

## 8. WebUI 信息架构

### 8.1 桌面端布局

```text
项目顶栏
┌──────────────┬────────────────────────────────────┬────────────────────┐
│ 六阶段流程   │ 当前阶段制作区                     │ 本阶段协作面板     │
│              │                                    │                    │
│ 创作设定     │ 阶段目标                           │ 当前状态           │
│ 内容文稿     │ 可编辑产物                         │ AI 建议            │
│ 画面设计     │ 预览 / 候选 / 时间线               │ 待处理问题         │
│ 分镜预演     │                                    │ 修改影响           │
│ 镜头制作     │                                    │ 历史版本           │
│ 剪辑成片     │                                    │ 生成详情           │
└──────────────┴────────────────────────────────────┴────────────────────┘
固定阶段操作栏：[上一步] [保存] [重新生成选中内容] [确认并继续]
```

### 8.2 项目顶栏

展示：

- 项目名称。
- 视频类型。
- 当前剧集。
- 自动保存状态。
- 自动创作 / 分步制作。
- 全片预览。
- 项目设置。

资产库不再作为与流程割裂的全局主入口；它作为“画面设计”的核心区域，同时可以保留全局快捷入口。

### 8.3 左侧流程

左侧只展示六个阶段，不展示后台任务。

每项展示：

- 阶段名称。
- 状态。
- 需要处理的数量。
- 当前是否选中。

不可用阶段允许查看说明，但主要操作应禁用并明确缺少的前置条件。

### 8.4 中央制作区

每个阶段采用统一页面骨架：

1. 阶段标题和一句话目标。
2. 当前产物摘要。
3. 主要编辑、选择或预览区域。
4. 问题和来源就地提示。
5. 固定底部操作栏。

默认不展示页面功能说明、技术术语、键盘快捷键和内部 Schema。

### 8.5 右侧协作面板

右侧不再固定展示四类运行任务，而是展示当前阶段的上下文：

- 当前正在做什么。
- AI 建议。
- 待处理问题。
- 修改影响范围。
- 本阶段版本。
- 生成详情。

“生成详情”展开后才显示：

- 任务步骤。
- 实时进度。
- 可解释的决策摘要。
- 最终输出。
- 错误和重试。
- 高级模式下的模型、Prompt 和原始数据。

不默认展示模型原始思考过程。需要透明度时，应展示来源、规则检查、决策摘要和中间产物，而不是不可控的内部推理文本。

### 8.6 响应式

- `>= 1536px`：三栏常驻。
- `1024px - 1535px`：流程 + 制作区，协作面板使用右侧抽屉。
- `< 1024px`：顶部阶段选择器 + 制作区，协作面板使用底部抽屉。
- 固定操作栏不得遮挡内容。
- 所有可点击卡片必须有明确选中态、悬停态、焦点态和保存反馈。

## 9. 场景预设适配

六阶段骨架在所有视频类型中保持不变，差异由 Profile 驱动。

| 阶段 | AI 漫剧 | 书籍导读 | 广告 | 历史故事 |
| --- | --- | --- | --- | --- |
| 创作设定 | 故事、受众、风格 | 书籍材料、导读角度、剧透 | 产品、卖点、转化目标 | 史料、叙事角度、事实要求 |
| 内容文稿 | 剧情结构、场景、对白 | 大纲、旁白、来源 | Hook、卖点、CTA | 事件线、旁白、来源 |
| 画面设计 | 角色、场景、道具 | 人物、书封、图表、关键物件 | 产品、品牌、使用场景 | 人物、地点、服装、地图 |
| 分镜预演 | 表演、动作、镜头 | 信息呈现、引用卡、图解 | 产品展示、节奏、CTA | 事件推进、资料画面 |
| 镜头制作 | 人物一致性、动作 | 事实准确、视觉锚点 | 产品一致性、品牌合规 | 历史形象、时代一致性 |
| 剪辑成片 | 情绪和节奏 | 信息密度和可理解性 | 转化节奏和品牌露出 | 事实、节奏和字幕 |

不为不同视频类型复制工作台组件，只为阶段提供场景化 ViewModel、文案和编辑器配置。

## 10. 核心画面元素与一致性资产

### 10.1 产品定义

“角色、场景、道具”扩展为普通用户更容易理解的“核心画面元素”。

建议统一抽象：

```ts
type VisualAnchorType =
  | 'character'
  | 'location'
  | 'object'
  | 'vehicle'
  | 'book_cover'
  | 'graphic_template'
  | 'brand_element'

interface VisualAnchor {
  id: string
  type: VisualAnchorType
  name: string
  description: string
  consistencyRequired: boolean
  canonicalImageId?: string
  locked: boolean
  variants: VisualAnchorVariant[]
}
```

分镜必须通过稳定 ID 绑定元素，而不是只在 Prompt 中重复名称：

```ts
interface ShotVisualAnchorRef {
  shotId: string
  visualAnchorId: string
  role: 'subject' | 'environment' | 'supporting'
  variantId?: string
}
```

### 10.2 书籍导读示例

《海底两万里》至少应识别：

- 鹦鹉螺号外观：`vehicle`，必须保持一致。
- 鹦鹉螺号关键内部空间：`location`，需要共享设计语言。
- 尼摩船长：`character`，仅在视频会重复展示时创建。
- 潜水服：`object`，需要与整体时代和技术风格一致。
- 引用卡和科学图解：`graphic_template`。

流程：

```text
内容文稿
  -> 自动识别核心画面元素
  -> 用户确认清单
  -> 生成标准候选图
  -> 自动质量检查
  -> 用户或系统采用并锁定
  -> 分镜绑定 VisualAnchor ID
  -> 图片和视频生成复用同一参考资产
```

### 10.3 与现有资产能力的关系

首期可通过领域适配器复用现有 Character、Location 和 Prop 存储；新 UI 和分镜只依赖 `VisualAnchor` 接口。

当现有数据结构无法表达载具、图表模板、标准图和跨镜绑定时，再进行最小数据库迁移。不要让新页面直接依赖“道具存储在 Location 表”之类历史实现。

## 12. 目标组件边界

建议使用阶段注册表和统一工作台骨架，避免在根组件继续堆积条件分支。

```text
components/workspace-v2/
  CreationWorkspaceShell.tsx
  CreationWorkflowRail.tsx
  CreationStageHeader.tsx
  CreationStageActionBar.tsx
  CreationAssistantPanel.tsx
  CreationTaskDetails.tsx
  stages/
    SetupStage.tsx
    ContentStage.tsx
    VisualDesignStage.tsx
    StoryboardPreviewStage.tsx
    ProductionStage.tsx
    EditStage.tsx
```

领域边界：

- Stage Registry：定义阶段、依赖、标签、状态和组件。
- Stage ViewModel：把现有 API、Episode、资产和 Run Stream 转成用户界面模型。
- Stage Command：保存、锁定、重生成、批准和继续。
- Impact Resolver：计算上游修改影响。
- Visual Anchor：统一核心画面元素和分镜绑定。
- Task Details：只负责运行可观测性，不决定业务阶段。

不要创建一个包含全部状态和操作的超大 Workspace Controller。每个阶段只依赖自己的 ViewModel 和 Command 接口。

## 14. 重构实施计划

本计划使用 `WR-*` 编号，避免与视频质量方案现有的 `P0/P1/P2/P3` 混用。

### WR-0：契约和迁移基线

#### 目标

在不改变现有行为的情况下建立新工作台所需的稳定契约。

#### 实施内容

- 定义 `CreationStageId`、用户可见状态和六阶段注册表。
- 定义旧路由到新路由的别名映射。
- 定义阶段 ViewModel、Command 和影响范围接口。
- 为 AI 漫剧和书籍导读建立阶段配置测试。
- 补齐当前关键路径的回归测试和基线截图。
- 增加临时工作台版本开关，仅用于迁移期。

#### 数据库变化

无。

#### 验收

- 新旧路由映射有单元测试。
- 现有 AI 漫剧和书籍导读流程不受影响。
- 六阶段状态可以由现有数据正确推导。

### WR-1：六阶段工作台骨架

#### 目标

先替换信息架构，不改生成核心。

#### 实施内容

- 新增六阶段流程栏。
- 新增统一阶段页头和固定操作栏。
- 将右侧固定四任务改为当前阶段协作面板。
- Run Stream 下沉到“生成详情”。
- 使用旧页面作为阶段内部临时内容，保证迁移可逐步进行。
- 完成桌面、平板和移动端布局。

#### 数据库变化

无。

#### 验收

- 用户只看到六个一级阶段。
- 书籍导读不再显示不适用的“生成解说稿/生成分镜”空任务。
- 旧 URL 可进入对应新阶段。
- 所有现有生成入口仍可用。

### WR-2：内容文稿可编辑闭环

#### 目标

让用户在进入画面设计前真正参与内容制作。

#### 实施内容

- 合并当前 ContentPlan 和 Script 页面。
- 新增 AI 漫剧剧本编辑器和书籍导读旁白编辑器。
- 支持段落排序、拆分、合并、删除和新增。
- 支持来源锚点查看和编辑。
- 支持局部重生成和锁定。
- 内容评审转为就地问题提示。
- 实现修改影响范围和下游 `needs_update`。

#### 数据变化

- 为关键内容单元增加最小版本和锁定信息。
- 优先复用现有 Clip 和 Artifact；仅在无法表达时增加字段或关联表。

#### 验收

- 书籍导读旁白可直接编辑并保存。
- 修改单段只影响对应下游对象。
- 锁定段落不会被自动重生成覆盖。
- 旧的 guide `screenplay` 数据可以无损读取。

### WR-3：画面设计与核心画面元素

#### 目标

在分镜之前锁定全片视觉方向和需要保持一致的对象。

#### 实施内容

- 合并 VisualPlan 和资产库主流程。
- 引入 `VisualAnchor` 领域接口。
- 自动识别人物、地点、物件、载具、书封和图表模板。
- 支持参考图候选、选择、锁定和变体。
- 为书籍导读补齐核心画面元素分析。
- 分镜通过 ID 绑定核心画面元素。
- 图片生成、视频生成和质量评审共享同一参考资产。

#### 数据变化

- 增加稳定的分镜到核心画面元素引用。
- 根据适配结果决定复用现有资产表还是增加最小新表。

#### 验收

- 《海底两万里》能够识别并创建“鹦鹉螺号”一致性资产。
- 用户锁定标准图后，所有相关分镜都显示绑定关系。
- 相关镜头生成请求包含同一参考资产。
- 修改无关文稿不会使已锁定资产失效。

### WR-4：分镜编辑与 Animatic

#### 目标

在高成本生成前完成镜头结构、时长和节奏确认。

#### 实施内容

- 新增分镜卡片和时间线双视图。
- 支持排序、拆分、合并、增加和删除镜头。
- 支持编辑画面描述、时长、屏幕文字和资产绑定。
- 生成临时旁白和低成本预览图。
- 构建 Animatic 播放器。
- 增加进入镜头制作前的成本和影响确认。

#### 数据变化

- 复用 Storyboard / Panel。
- 增加最小顺序、版本和临时预演信息。

#### 验收

- 用户可以不生成最终视频就完整预览时长和节奏。
- 分镜修改后只标记受影响镜头需要更新。
- 资产绑定在编辑和重排后保持稳定。

### WR-5：统一镜头制作与异常队列

#### 目标

把图片、视频、旁白和质量处理组织为一个可操作的生产工作区。

#### 实施内容

- 统一镜头生产状态和批量操作。
- 将图片、首尾帧、视频和旁白状态集中到镜头行。
- 默认展示最佳候选和最终采用结果。
- 自动质量评审和修复在后台执行。
- 单独展示需要人工处理的异常队列。
- 支持单镜头局部修复、重生成和锁定。
- 将运行详情按选中镜头和当前任务过滤。

#### 数据变化

- 复用现有质量 Artifact 和候选记录。
- 补齐素材版本与当前采用关系。

#### 验收

- 普通用户无需逐张检查全部候选。
- 用户可以从异常项直接定位问题和修复操作。
- 书籍导读和 AI 漫剧共享同一镜头制作工作区。
- 视频生成门禁不能被新 UI 绕过。

### WR-6：剪辑成片与交付

#### 目标

闭合从镜头素材到最终视频的制作流程。

#### 实施内容

- 时间线编辑。
- 字幕和旁白轨道。
- 音乐、音效和音量控制。
- 转场和镜头时长调整。
- Rough Cut 全片评审。
- Pickup List 和定向回流。
- Final QC。
- 导出规格和任务状态。

#### 数据变化

- 增加项目级编辑时间线和导出版本。

#### 验收

- 用户可以在同一工作台完成预览、修改和导出。
- 全片问题能够回流到具体内容、资产、分镜或镜头。
- 导出前有明确的质量和规格检查结果。

## 15. 推荐交付顺序

```text
第一批：WR-0 + WR-1
  目标：先让流程和界面不乱，保持现有能力可用。

第二批：WR-2 + WR-3
  目标：让用户能在分镜前参与内容和视觉决策，解决导读一致性资产问题。

第三批：WR-4
  目标：增加低成本分镜预演，避免过早进入高成本生成。

第四批：WR-5
  目标：统一生产和质量异常处理，减少人工逐项检查。

第五批：WR-6
  目标：完成剪辑、反馈回流和最终交付。
```

不建议一次性同时重写六个阶段。每批都必须保持旧数据可读、旧任务可恢复和核心生成链可用。

## 17. 指标

产品重构完成后应持续记录：

- 首次完成六阶段流程的成功率。
- 用户在每个阶段的停留时间。
- 自动模式转分步模式的比例。
- 内容文稿修改率。
- 核心画面元素人工修正率。
- Animatic 后进入高成本生成的比例。
- 上游修改导致的全量重跑率。
- 自动修复成功率和人工异常率。
- 成片前补镜数量。
- 项目完成率和导出成功率。

重点不是降低所有人工操作，而是减少无效检查和大范围返工，让人工集中在方向、审美和异常判断。

## 18. 不建议的实现方式

- 继续在七阶段导航上叠加更多只读 Tab。
- 把六阶段直接映射为六个固定 Worker。
- 为每个视频类型复制一套页面和状态机。
- 默认展示原始 JSON、Prompt、模型参数和运行日志。
- 上游修改后立即删除所有下游结果。
- 用户只能整阶段重生成，不能局部修改和锁定。
- 只创建资产库条目，却不让分镜通过 ID 绑定资产。
- 只在 Prompt 中重复“保持一致”，却不提供标准参考图。
- 在没有 Animatic 的情况下直接批量生成视频。
- 一次性重写全部 Worker、API、数据库和 UI。

## 19. 最终验收口径

满足以下条件后，目标工作台才算完成：

1. 非开发用户不需要理解模型、Prompt、Run Stream 或内部 JSON 就能完成项目。
2. 用户始终知道当前阶段、待处理事项和下一步。
3. 每个一级阶段都允许用户进行有效制作操作。
4. 自动模式能够连续执行，分步模式能够在阶段间稳定暂停。
5. 内容、视觉、分镜和镜头都支持局部修改、锁定和定向更新。
6. 书籍导读能够识别并复用核心人物、地点、物件或载具形象。
7. 高成本生成前可以通过 Animatic 检查内容、时长和节奏。
8. 质量异常能够定位到具体镜头并给出明确处理动作。
9. 不同视频类型共享工作台骨架，但阶段内容和质量规则符合各自场景。
10. 用户能够在同一工作台完成从材料输入到成片导出的完整流程。
