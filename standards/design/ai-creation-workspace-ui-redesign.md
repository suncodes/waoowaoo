# AI 创作工作台完整流程 UI 重构方案

- 状态：UI-1 / UI-2 / UI-3 已实现，UI-4 待后续
- 适用项目：`waoowaoo`
- 更新时间：2026-07-17
- 关联方案：`standards/design/video-generation-quality-optimization.md`
- 实施范围：工作流导航、内容策划工作区、视觉方案工作区、统一运行详情、响应式布局

## 1. 背景与问题

P0 + P1 + P2 已经新增以下正式产物：

- `CreativeBrief`
- `ContentPlan`
- `ContentReview`
- `DirectorTreatment`
- `ProductionBible`
- 内容规划、剧本生成、视觉规划和分镜生成四类 Run Stream

现有 WebUI 仍沿用“故事、剧本、分镜、成片”的旧导航，导致新增能力只存在于后台链路：

1. 内容规划和视觉规划没有正式查看入口。
2. Planning 运行时只显示通用 Toast 和裸 `planning` 状态，用户无法判断实际进度。
3. 任意操作运行时，旧导航会将所有阶段标记为 `processing`，缺少阶段粒度。
4. 剧本和分镜运行详情使用全屏浮层，打断当前工作；Planning 又没有接入浮层，形成不一致。
5. 运行完成后立即 `reset()`，本次会话中的步骤和输出无法回看。
6. “当前选中页面”和“阶段完成状态”混用，无法表达失败、待处理和上游修改后的过期状态。

## 2. 设计目标

本轮设计必须满足：

1. 用户一眼看到完整制作流程、当前位置和每个阶段状态。
2. 所有持久化规划产物均有正式工作区，可随时回看。
3. 长任务运行期间始终可以查看当前步骤、总进度、阶段输出和错误原因。
4. 透明展示不等于新增人工门禁；默认仍可自动连续执行。
5. AI 漫剧与书籍导读复用同一套页面和路由，只替换场景化标签与数据结构。
6. 复用现有 Episode JSON、Run Stream、`SegmentedControl`、玻璃主题和 Lucide 图标。
7. 不引入新的后端接口、数据库字段、通用工作流引擎或复杂版本编辑器。

## 3. 核心信息架构

桌面端采用三栏工作台：

```text
项目与剧集顶栏
┌────────────────┬──────────────────────────────────┬────────────────────┐
│ 制作流程       │ 当前阶段工作区                   │ 运行详情           │
│                │                                  │                    │
│ 输入与目标     │ 阶段标题、状态与主要产物         │ 任务切换           │
│ 内容策划       │ 子视图 / 编辑区 / 生成结果       │ 步骤列表           │
│ 剧本或解说稿   │                                  │ 当前输出           │
│ 视觉方案       │                                  │ 失败与重试         │
│ 分镜与画面     │                                  │                    │
│ 视频与声音     │                                  │                    │
│ 成片与导出     │                                  │                    │
└────────────────┴──────────────────────────────────┴────────────────────┘
```

响应式规则：

- `>= 1536px`：左侧流程、中央工作区、右侧运行详情三栏同时展示。
- `1024px - 1535px`：左侧流程和中央工作区展示；运行详情通过固定按钮打开右侧抽屉。
- `< 1024px`：流程改为横向可滚动阶段选择器；运行详情改为底部抽屉。
- 页面不得出现横向溢出，固定元素不得遮挡顶栏或主要操作。

## 4. 制作阶段定义

| 路由 ID | 通用名称 | AI 漫剧标签 | 书籍导读标签 | 完成产物 |
| --- | --- | --- | --- | --- |
| `config` | 输入与目标 | 故事与目标 | 书籍材料与目标 | 原文、VideoProfile、画幅与风格 |
| `content-plan` | 内容策划 | 剧情结构 | 导读结构 | CreativeBrief、ContentPlan、ContentReview |
| `script` | 文稿 | 剧本 | 解说稿 | Clips、Screenplay 或 Narration |
| `visual-plan` | 视觉方案 | 导演与视觉方案 | 导读视觉方案 | DirectorTreatment、ProductionBible |
| `storyboard` | 分镜与画面 | 剧情分镜 | 图文分镜 | Storyboard、Panel、图片与质量状态 |
| `videos` | 视频与声音 | 视频与声音 | 视频与旁白 | 单镜头视频、配音与音频 |
| `editor` | 成片与导出 | 成片与导出 | 成片与导出 | P3 范围，当前保留禁用入口 |

资产库、项目设置和图片质量策略属于跨阶段工具，不作为线性制作阶段。

## 5. 阶段状态模型

导航状态统一为：

```text
not_started  未开始
ready        可开始
running      生成中
attention    待处理
completed    已完成
failed       失败
stale        已过期
```

本轮实现 `not_started / ready / running / completed / failed`；`attention / stale` 保留在类型和 UI 能力中，待后续接入质量异常和依赖失效检测。

状态判定原则：

1. Run Stream 正在运行时，只将对应制作阶段标记为 `running`。
2. Run Stream 失败时，将对应阶段标记为 `failed`。
3. 持久化产物存在时，阶段标记为 `completed`。
4. 上游前置产物已经存在、当前产物尚未生成时，阶段标记为 `ready`。
5. 当前选中态由路由独立表达，不复用阶段状态字段。

## 6. 内容策划工作区

路由：`stage=content-plan`

采用三个子视图：

### 6.1 创作简报

展示：

- 创作目标
- 目标受众
- 受众承诺
- 目标时长
- 内容语气
- 必须包含
- 必须避免

### 6.2 内容结构

AI 漫剧展示：

- 标题、Logline、主题
- Narrative Beats
- 每个 Beat 的目的、摘要、预计时长和来源锚点

书籍导读展示：

- 标题、核心论点、推荐角度
- 导读大纲的问题与结论
- Guide Segments 的旁白、视觉目的、视觉提示、剧透等级和来源锚点

### 6.3 检查结果

展示：

- 总分
- Profile 匹配分
- 来源支持分
- 状态：通过、警告或阻断
- 问题列表和调整建议

本轮页面为只读，不增加强制确认或局部编辑接口。

## 7. 视觉方案工作区

路由：`stage=visual-plan`

采用两个子视图：

### 7.1 导演方案

展示：

- 叙事策略
- 节奏
- 镜头语言
- 转场策略
- 声音策略

### 7.2 视觉规范

展示：

- 视觉风格
- 灯光基线
- 调色基线
- 构图规则
- 连续性规则
- 禁止模式

镜头级执行结果继续在“分镜与画面”阶段展示，避免视觉方案与实际分镜职责重叠。

## 8. 统一运行详情

右侧运行详情统一接入：

1. 内容策划 `contentPlanStream`
2. 剧本/解说稿生成 `storyToScriptStream`
3. 视觉方案 `visualPlanStream`
4. 分镜生成 `scriptToStoryboardStream`

每个任务显示：

- 任务名称与运行状态
- 总体百分比
- 当前步骤和步骤总数
- 步骤列表及完成、运行、失败、阻塞状态
- 当前步骤的最终输出
- 错误信息
- 停止和可重试操作

展示规则：

- 不直接展示模型原始思考过程。
- 如果流中同时存在 reasoning 和 final，只展示 final。
- 运行中尚无 final 时展示当前动作和步骤状态。
- 完成后不立即 reset，保留本次会话运行详情。
- 刷新页面后，正式产物由阶段工作区继续展示；正在运行的任务继续使用现有恢复机制。

## 9. 自动执行体验

现有业务流程保持不变：

```text
AI 漫剧：
输入 -> 内容策划 -> 剧本 -> 视觉方案 -> 分镜

书籍导读：
输入 -> 内容策划 -> 解说稿 -> 视觉方案 -> 图文分镜
```

界面行为调整为：

1. 用户点击开始创作后，当前运行阶段在流程栏中高亮为 `running`。
2. 右侧详情自动选择正在运行的任务。
3. 用户可以切换到已完成阶段查看产物，不中断后台执行。
4. 自动链路继续向后执行，不要求用户逐阶段点击确认。
5. 失败时保留所在阶段、错误和已经完成的上游产物。

## 10. 组件边界

建议组件结构：

```text
components/
  WorkspaceWorkflowRail.tsx
  WorkspaceTaskPanel.tsx
  ContentPlanStage.tsx
  VisualPlanStage.tsx
  planning/
    PlanningStagePrimitives.tsx
  workspace-run-types.ts
```

职责：

- `useWorkspaceStageNavigation`：只负责将产物和 Run 状态映射为流程项。
- `WorkspaceWorkflowRail`：只负责阶段导航和状态展示。
- `ContentPlanStage` / `VisualPlanStage`：只负责持久化产物展示。
- `WorkspaceTaskPanel`：只负责四类 Run Stream 的统一可观测性。
- `useWorkspaceExecution`：继续负责执行流程，不承担页面展示结构。

## 12. 验收标准

1. 页面始终能看到完整七阶段流程。
2. 内容策划和视觉方案可以通过 URL 与界面直接访问。
3. Planning 运行时可以查看真实步骤，不再只显示 `planning`。
4. 四类文本生成任务使用同一套运行详情 UI。
5. 只有实际运行的阶段显示为生成中。
6. 完成后的规划产物可以回看，切换阶段不会丢失。
7. AI 漫剧显示“剧本”，书籍导读显示“解说稿”。
8. 1024px 以下不出现三栏挤压和页面横向滚动。
9. 不改变现有生成任务、数据持久化和质量门禁行为。

## 13. 非目标

本轮不实现：

- ContentPlan 或 VisualPlan 在线编辑。
- 多版本对比和回滚。
- 通用工作流编排器。
- P3 Animatic、Rough Cut、Final QC。
- 成片时间线和导出能力。
- 数据库新增字段或迁移。
