# AI 视频创作工作台引导式流程 V4

- 状态：本轮代码实施完成，待真实浏览器交互验收
- 日期：2026-07-20
- 实施范围：现有工程内重构，不新建独立工程
- 目标用户：不熟悉模型、提示词和视频生产流程的内容创作者

## 1. 问题定义

当前六阶段工作台已经具备成果展示、编辑和生成能力，但交互仍然接近自由导航的后台管理界面：

1. 未满足前置条件的阶段仍然可以进入。
2. 阶段、子视图和后台任务使用同一层级表达，用户无法判断先后关系。
3. 同一能力可能在多个页面出现，例如画面需求识别和核心画面识别。
4. 按钮只描述动作，不说明动作的直接结果和后续影响。
5. 未分析、分析结果为空、结果待确认和结果失效缺少独立状态。
6. 上游修改后虽然会标记下游失效，但没有形成明确的恢复路径。

本轮目标不是增加更多说明，而是把工作台改为由状态驱动的制作流程。

## 2. 交互原则

### 2.1 一个页面只有一个主要动作

主要按钮必须描述结果，例如：

- `确认文稿并提取画面元素`
- `确认画面元素并进入画面准备`
- `确认核心画面并生成分镜`

重新生成、返回修改和展开详情属于次要操作，不与主要动作竞争。

### 2.2 只约束真实依赖

后续阶段在前置成果未确认时锁定。已经产生结果的历史阶段仍允许查看，但生成和确认动作必须遵守最新门禁。

### 2.3 生成完成不等于确认完成

异步任务完成后自动进入结果视图，但只有用户确认成果后才解锁下一阶段。

### 2.4 空结果是正式结果

系统必须区分：

```text
未分析 -> 分析中 -> 待确认（可以为 0 项） -> 已确认 -> 已失效
```

零项结果必须显示“分析完成，未发现需要固定形象的画面元素”，并允许用户确认无需求或手动补充。

## 3. 顶层流程和门禁

用户可见流程保持六阶段：

```text
创作设定
-> 内容创作
-> 画面准备
-> 分镜预演
-> 镜头制作
-> 剪辑成片
```

门禁矩阵：

| 目标阶段 | 解锁条件 | 上游修改后的行为 |
| --- | --- | --- |
| 内容创作 | 已保存创作材料 | 保持可进入 |
| 画面准备 | 文稿已确认，画面元素已确认 | 返回内容创作并提示更新画面元素 |
| 分镜预演 | 画面方案和核心画面已确认 | 旧分镜可查看，但标记需要更新 |
| 镜头制作 | 已生成分镜 | 旧镜头可查看，但禁止基于失效分镜继续批量生成 |
| 剪辑成片 | 已有可用镜头视频 | 保留已有成片数据并提示受影响范围 |

未开始且前置条件不满足的阶段显示锁定状态，不响应导航点击，并直接显示需要先完成的阶段。

## 4. 内容创作顺序

内容创作取消三个平级 TAB，改成三个顺序子步骤：

```text
1. 内容结构
2. 剧本文稿 / 解说文稿
3. 画面元素
```

### 4.1 内容结构

- 展示创作目标、受众、内容结构和检查结果。
- 创作目标、结构和检查结果在同一页面分区展示，不再使用嵌套 TAB。
- 已有结构后才能进入文稿。

### 4.2 文稿

- 书籍导读展示可编辑解说文稿。
- AI 漫剧展示可编辑分场剧本。
- 未保存内容、生成中的 AI 建议和未处理候选会阻止确认。
- 主要操作为`确认文稿并提取画面元素`。

### 4.3 画面元素

画面元素回答“后续需要准备哪些重复使用或需要保持一致的对象”，不直接生成最终图片。

支持状态：

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 未分析 | 尚未根据当前文稿提取 | 提取角色、场景和关键物品 |
| 分析中 | 模型任务运行中 | 查看进度 |
| 待确认 | 已得到结果，允许为 0 项 | 确认并进入画面准备 |
| 已确认 | 当前内容版本已确认 | 进入画面准备 |
| 已失效 | 文稿在分析后发生修改 | 根据新文稿重新提取 |

分析结果保存稳定资产 ID，界面只展示本次内容实际关联的资产，不再根据 Clip 名称进行二次过滤。

## 5. 画面准备边界

内容创作负责确认“需要什么”，画面准备负责确认“最终长什么样”。

```text
画面元素清单
-> 整体画面方向
-> 核心画面候选
-> 定稿参考图
-> 分镜绑定
```

若画面元素分析结果为零并已确认，画面准备不得再次强制用户执行相同识别任务。

## 6. 数据状态

继续使用 `contentPlan._workspace`，不增加数据库表。新增：

```ts
assetRequirements: {
  status: 'not_started' | 'needs_review' | 'approved' | 'stale'
  analyzedRevision: number | null
  analyzedAt: string | null
  approvedAt: string | null
  assetIds: string[]
}
```

规则：

1. 内容首次生成时为 `not_started`。
2. 分析完成后为 `needs_review`，即使 `assetIds` 为空。
3. 用户确认后为 `approved`。
4. 内容版本变化后，已分析结果变为 `stale`。
5. 重新分析覆盖旧的资产 ID 清单并回到 `needs_review`。
6. 旧项目没有该字段时按兼容流程读取，不阻断已经存在的下游成果。

## 7. 导航与反馈

### 7.1 左侧阶段栏

- 显示第几步、阶段状态和锁定原因。
- 未满足依赖的未开始阶段不可点击。
- 已完成、待确认、需要更新和已有历史成果的阶段允许查看。

### 7.2 底部操作栏

- 保留一个主要按钮和一个返回按钮。
- 不可操作时在按钮旁直接显示原因，不只依赖悬浮提示。
- 子步骤内的“上一步”优先返回上一个子步骤，而不是直接离开整个阶段。

### 7.3 运行详情

- 当前生成任务继续自动展开。
- 技术步骤和流式输出保留在生成详情中，不进入主页面。
- 任务完成后主页面刷新成果并进入待确认状态。

## 8. 实施范围

本轮实施：

1. 顶层阶段访问门禁和锁定原因。
2. 内容创作顺序子步骤。
3. 内容结构页面去除嵌套 TAB。
4. 画面元素状态持久化、零结果确认和失效处理。
5. 画面元素使用稳定资产 ID 展示。
6. 底部主要动作根据子步骤和状态变化。
7. 中英文界面文案和聚焦单元测试。

本轮不实施：

- WR-4 Animatic 编辑器。
- WR-5 镜头异常队列重构。
- WR-6 完整剪辑时间线。
- 内容结构的复杂多人协作和评论系统。

## 9. 验收口径

1. 用户不能进入尚未解锁且没有历史成果的后续阶段。
2. 锁定阶段明确显示需要先完成哪一步。
3. 内容创作按结构、文稿、画面元素顺序操作。
4. 文稿确认后可以在一次主要操作中启动画面元素提取。
5. 分析结果为零时显示正式完成状态，而不是继续显示“尚未识别”。
6. 画面元素确认前不能进入画面准备。
7. 修改文稿后，画面元素变为需要更新。
8. 画面元素确认后，页面进入画面准备。
9. 已确认零画面元素时，画面准备不再次要求识别。
10. 类型检查、相关单元测试和生产构建通过。

## 10. 2026-07-20 实施结果

已完成：

1. 顶层六阶段新增访问门禁、锁定图标和明确的前置阶段提示。
2. 直接进入未解锁阶段时展示阻塞页，不再渲染不可操作的后续页面。
3. 内容创作改为内容结构、文稿、画面元素三个顺序子步骤。
4. 内容结构移除创作目标、结构、检查结果之间的嵌套 TAB。
5. 底部操作栏根据当前子步骤显示唯一主要动作和执行结果提示。
6. 新增画面元素分析状态、分析内容版本、确认时间和稳定资产 ID 清单。
7. 文稿修改后，已分析的画面元素自动标记为需要更新。
8. 画面元素分析读取当前 Clip 文稿，并把零项结果保存为正式待确认成果。
9. 画面元素界面区分未分析、分析中、待确认、已确认和已失效。
10. 已确认零项结果后，画面准备不再重复要求识别核心画面。
11. 画面方案已失效时，重新提取画面元素不会错误恢复旧方案的可确认状态。
12. 服务端画面确认命令对新状态执行画面元素确认门禁，旧项目保持兼容。
