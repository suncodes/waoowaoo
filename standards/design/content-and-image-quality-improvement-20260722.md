# 文稿、剧本与图片质量整体优化落地方案

- 状态：P0 已实施并通过聚焦验证，P1 待后续迭代
- 日期：2026-07-22
- 范围：书籍导读与剧情内容计划、视觉计划、资产图、分镜图、视觉质检与自动修复
- 依据：`waoowaoo-diagnostic.zip` 中的运行快照、模型调用、质量审核和媒体样本

## 1. 目标

本方案不把质量问题简化为“补更多提示词”，而是建立从内容到图片的可验证闭环：

```text
来源与受众约束
  -> 内容计划与独立评审
  -> 可执行旁白 / 剧本
  -> 视觉计划与资产绑定
  -> 按渲染职责生成基础画面
  -> 多候选质量审核
  -> 有界自动修复 / 人工升级
```

目标结果：

1. 文稿事实边界清楚，模型常识不伪装成已验证事实。
2. 旁白时长保留剪辑、转场和片尾缓冲，不再完全卡满目标时长。
3. 每个镜头只表达一个主要视觉事件，不让单张图片承担“混剪”或多场景转场。
4. 已有角色、场景和道具必须使用稳定资产 ID，并进入图片参考链路。
5. 道具设定图只出现同一道具，不因项目风格引入角色、场景或既有 IP 形象。
6. 自动质量模式使用多个修复候选，减少单次随机生成决定最终质量。

## 2. 诊断证据

### 2.1 图片质量

- 20 次分镜图审核中，仅 6 次通过，14 次为可修复，平均分 65.6。
- 高频问题为主体错误、风格冲突、构图错误、场景错误、未指定角色和文字错误。
- 19 次审核只有 1 个候选；唯一一次 3 候选审核成功选出了合格结果，同时淘汰了包含海绵宝宝、章鱼哥的错误候选。
- 道具和场景资产生成没有进入分镜视觉质量闭环。

### 2.2 资产与状态

- 视觉计划中的 `assetRefs` 未稳定进入持久化分镜，导致参考资产链路断开。
- 角色分析结果、当前角色资产、视觉计划和 storyboard 曾出现不一致状态。
- `composite` 目前仍由统一文生图处理，模型被要求在单图中模拟实拍、边框和混剪，职责冲突。

### 2.3 内容质量

- 书名模式下内容来源是 `model_knowledge`，置信度低于质量策略要求。
- 内容审核已识别来源不足和时长无缓冲，但 warning 计划仍可继续生产。
- 导读镜头曾混入过多剧情复述、多个事实判断和多个视觉事件。

## 3. 根因与修复策略

| 根因 | 修复策略 | 验收证据 |
| --- | --- | --- |
| 风格词携带内容语义，诱发已有角色 | 资产提示词最后追加隔离约束；禁止人物、脸、五官、文字、IP 角色和环境元素 | 道具提示词测试；人工抽样三视图 |
| 道具描述缺少唯一身份锚点 | 强化材质、轮廓、部件和三视图一致性；同一道具必须跨视图保持结构 | 三视图主体一致，无角色串入 |
| 视觉计划资产引用被忽略 | 解析、校验并保留 `assetRefs`；显式引用必须来自资产库 | 单测证明 assetRefs 进入持久化参数 |
| 单图承担混剪/多场景 | 提示词强制“一张图、一个时空、一个主要视觉事件” | 视觉计划与单图模板不再要求拼贴/混剪 |
| composite 伪装成单图生成 | composite 只生成可供后续合成的基础底图，不在底图中伪造多素材拼贴 | 单图模板包含渲染职责约束 |
| 图片文字错误 | 图片只生成无字底图；准确文字由 `onScreenText` 和后续合成负责 | 图片模板禁止任何文字，视觉计划不把准确文字写入 imagePrompt |
| 自动修复随机性高 | 结构性重生默认生成多个候选，局部编辑保留少量候选；统一复审 | 自动修复测试证明多候选持久化与复审 |
| 内容计划卡满时长 | 内容提示词按目标时长的 85%～92%规划旁白，预留制作缓冲 | 内容提示词回归测试；内容审核规则 |
| 模型常识被写成确定事实 | 未验证来源使用保守表达，禁止排名、数量、引语和因果归功等高风险断言 | 内容提示词和评审提示词回归测试 |

## 4. 提示词合同

### 4.1 内容计划

- 开场只承载一个核心反差或问题。
- 每段只回答一个问题，并明确观众收获。
- 旁白按中文口播约 3.5～4.2 字/秒估算。
- 总旁白时长控制在目标时长的 85%～92%。
- 仅书名输入时，使用“约、被普遍认为、可理解为”等保守表达。
- 禁止无来源的全球排名、精确数量、逐字引语和“全部实现”等绝对化判断。
- `visualHints` 描述信息功能，不直接规定多场景拼贴。

### 4.2 视觉计划

- `assetRefs` 使用资产库中的精确 `id/kind/name`。
- 当画面出现已有角色、场景或道具时必须引用对应资产。
- `generated_image`：单一时空、单一主要事件。
- `text_card`：只生成无字底图和留白，准确文字放在 `onScreenText`。
- `composite`：只生成一个基础底图或单个前景素材，不在一张图中伪造新闻混剪、多个海域或多张封面。
- 风格只控制线条、色块、材质和光色，不自动引入风格作品中的角色、建筑或标志物。

### 4.3 资产图

- 资产主体是唯一内容。
- 三视图必须是同一道具的同一设计，不得把不同对象分别放入不同区域。
- 白底资产图禁止环境背景、人物、手部、脸、五官、表情、文字、水印、徽标和已有 IP 角色。
- 项目风格只能作用于形状语言、线条和配色，不能覆盖资产隔离规则。

### 4.4 自动修复

- `SUBJECT_MISMATCH`、`CONTINUITY_ERROR` 等结构错误走重生。
- 局部风格、构图和轻微道具错误可走编辑。
- 重生默认 3 个候选，编辑默认 2 个候选，候选统一复审。
- 达到最大修复次数后进入人工处理，不继续无限消耗。

## 6. 验收标准

### 内容

- 计划提示词明确时长缓冲、来源边界、单段职责和视觉可执行性。
- 评审提示词能够识别绝对化事实、伪精确结论、剧情复述和多事件视觉提示。

### 图片

- 道具最终提示词以资产隔离规则结束，风格规则不能覆盖隔离规则。
- 视觉计划中引用不存在的资产 ID 会触发校验失败并进入计划修复。
- 显式资产引用能够进入最终 `assetRefs` 和 storyboard 字段。
- 自动修复可以产生并持久化多个候选，并把全部候选交给质量审核。

### 工程

- 聚焦单元测试通过。
- 小说推广提示词的中英文占位符与语义回归检查通过。
- `npm run typecheck` 通过。
- 不修改用户已有的 `.gitignore` 变更，不执行 Git 提交。

## 7. P0 实施结果

已完成：

1. 内容计划与内容评审增加时长缓冲、来源边界、轻剧透、单段职责和单图可执行性规则。
2. 分镜规划取消按字符数机械拆镜，按时长和主要视觉事件控制镜头密度。
3. 视觉计划增加 `assetRefs` 输出、解析、精确校验、计划修复、锚点合并与持久化绑定。
